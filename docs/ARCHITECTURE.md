# Архитектура и API

## Хранение

Локально используется `DATA_DIR`, по умолчанию `data/`. Данные пишутся через временный файл, fsync и rename. Локальный режим рассчитан на один процесс с постоянным диском.

В Cloud Run используется отдельная база Firestore и закрытый Cloud Storage bucket. Пример путей Firestore:

```text
svm_rakennus_site/main/state/settings
svm_rakennus_site/main/leads/<random-id>
svm_rakennus_site/main/media/<random-id>
```

Каждый документ хранит JSON в строковом поле `payload`. Новая заявка создаётся отдельно и не переписывает старые. Объекты GCS размещаются по пути `<namespace>/<media-id>`. Метаданные определяют публичность; сам bucket закрыт от анонимных посетителей.

Обновления настроек защищены ревизией и Firestore `currentDocument.updateTime`. При конкурентном изменении возвращается 409. Хеш пароля и версия авторизации исключаются из контента, выдаваемого админпанели, и backup JSON.

## Заявка и email

Форма -> проверка Origin, подписанного токена и полей -> приватные вложения -> отдельная заявка -> SMTP -> фиксация результата -> ответ посетителю.

Токен формы служит ключом идемпотентности. Повтор запроса с тем же токеном не создаёт вторую заявку или письмо. Браузер сохраняет токен для повтора после сетевой ошибки и меняет после успеха.

При сбое SMTP заявка остаётся со статусом email `failed`. Повтор запускается из админпанели. Статус `sending` блокирует параллельную попытку на 15 минут. При завершении процесса между доставкой письма и фиксацией статуса нужна ручная проверка доставки перед повтором.

Письма содержат ссылки на вложения; для открытия требуется вход. Файлы не включаются непосредственно в email. Автоподтверждение клиенту отключено по умолчанию; после включения его доставка является дополнительной попыткой и не блокирует сохранение заявки.

## Публичные маршруты

| Метод и адрес | Результат |
|---|---|
| `GET /` | 302 на основной язык, query string сохраняется |
| `GET /en/`, `/fi/` | Главная страница |
| `GET /{lang}/services/{slug}/` | Услуга |
| `GET /{lang}/projects/{slug}/` | Объект |
| `GET /{lang}/privacy/`, `/cookies/`, `/terms/` | Юридические страницы |
| `GET /{lang}/thank-you/` | Благодарность для отправки без JS; noindex |
| `GET /robots.txt`, `/sitemap.xml` | Автоматическая генерация |
| `GET /api/form-token` | Подписанный токен на 30 минут |
| `POST /api/lead` | multipart/form-data; создание заявки |
| `GET /media/{id}` | Публичный или авторизованный приватный файл |
| `GET /healthz` | Проверка HTTP-процесса |

`/healthz` не проверяет SMTP или базу: это liveness endpoint.

## Админ-маршруты

| Метод и адрес | Назначение |
|---|---|
| `GET /admin` | Интерфейс входа и кабинет |
| `POST /api/login` | Вход: JSON с полем password |
| `GET /api/admin/session` | Сессия, CSRF и предупреждение о пароле |
| `POST /api/admin/logout` | Завершение текущей сессии |
| `GET /api/admin/state` | Контент без хеша пароля |
| `PUT /api/admin/state` | Валидация и публикация с текущей revision |
| `POST /api/admin/password` | Смена пароля и завершение старых сессий |
| `GET /api/admin/media` | Публичная медиабиблиотека |
| `POST /api/admin/media` | Один файл в поле file |
| `DELETE /api/admin/media?id=...` | Удаление неиспользуемого файла |
| `GET /api/admin/leads` | Список заявок |
| `PATCH /api/admin/leads` | ID, статус, заметки |
| `DELETE /api/admin/leads?id=...` | Заявка и активные вложения |
| `GET /api/admin/export` | CSV с защитой от formula injection |
| `GET /api/admin/backup` | Контент без секретов и заявок |
| `POST /api/admin/email-test` | Проверка SMTP |
| `POST /api/admin/retry-email` | Повтор уведомления по ID |
| `POST /api/admin/retention` | Подтверждённая очистка старых заявок |

Изменяющие админ-запросы требуют сессию, совпадение Origin и X-CSRF-Token. Сессия - 8 часов. Cookies: HttpOnly, SameSite=Strict, Secure в production. Пароли: PBKDF2-HMAC-SHA256, случайная соль, 600 000 итераций. Токены - crypto/rand.

## Ограничения выпуска

- Один владелец и пароль; роли сотрудников не реализованы.
- До 100 услуг, объектов, FAQ, документов и отзывов; до 250 redirect-правил.
- Контент настроек до 700 KB; фотографии хранятся отдельно.
- До 3 файлов по 8 MB на заявку: JPG/JPEG, PNG, WebP, GIF, PDF.
- Firestore читается страницами по 300 документов. Админ-список загружается целиком, показывается по 25 строк; предел чтения коллекции - 20 000 записей и 32 MiB JSON payload. Для большого CRM нужна серверная пагинация и архивирование.
- Rate limit действует на экземпляр Cloud Run. Распределённый WAF и CAPTCHA не включены.
- Используются браузерные SDK; серверные Meta CAPI, TikTok Events API и LinkedIn CAPI не включены.
- Cloud-доступ - runtime service account и metadata token. Локальная разработка использует файловый store; автоматическая поддержка gcloud ADC не реализована.

CSP разрешает перечисленные платформы. Для дополнительных внешних SDK и custom tags в GTM нужно расширить allowlist в app.go.

## Отличия SVM Rakennus

Основная версия fi, второй язык en. Публичного языка uk нет: украинские словари доступны только редактору. Админпанель и email владельцу используют украинский. Настройки paper, ink, surface, accent проверяются как шестизначные hex-цвета; headingFont принимает serif или sans. JS-файл admin-help.js содержит словарь и перевод технических ошибок.
