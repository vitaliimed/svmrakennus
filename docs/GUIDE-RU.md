# SVM Rakennus - сайт и админпанель

Полная инструкция по запуску и управлению. Go / Google Cloud Run. Основная версия Suomi (финская), вторая English. Админпанель украинская. Версия проекта 2.0, 10 октября 2026.

## 1. Что подготовлено

Проект разработан для компании, которая выполняет ремонт и реновацию существующих зданий, демонтаж, внутренние строительные работы, терасы, монтаж балконов и остекления, а также palokatkotyöt - противопожарную герметизацию проходок.

Назначение сайта - презентация компании во время прямых переговоров с частными клиентами, подрядчиками и строительными организациями. Каталога типовых домов, онлайн-магазина и фиксированных цен нет. На страницах описан индивидуальный расчёт сметы и письменное согласование условий.

| Область | Возможности |
|---|---|
| Публичный сайт | Главная, 6 услуг, отдельные страницы услуг и объектов, галерея, FAQ, документы, отзывы, контакты, юридические страницы |
| Языки | Suomi по умолчанию и English; переключатель сохраняет текущую страницу. Украинские переводы доступны только редактору |
| Дизайн | Скандинавское оформление: тёплый светлый фон, природный зелёный акцент, крупные фотографии, заголовки с засечками, асимметричное портфолио |
| Админпанель | 15 вкладок на украинском, финские и английские тексты с украинскими пояснениями, замена изображений, загрузка с ПК, добавление и сортировка записей, переключение блоков |

Название компании - SVM Rakennus. Логотип создан как заменяемое оформление для этой версии; если есть фирменный логотип, загрузите его. Телефон, email и примеры объектов пока демонстрационные. Иллюстрации созданы для показа дизайна, а не являются фотографиями ваших выполненных работ. Отзывы и сертификаты необходимо добавить самостоятельно: выдуманных подтверждений в комплекте нет.

## 2. Самый быстрый локальный запуск

1. Распакуйте архив. Откройте терминал в папке `svm-rakennus`.
2. Установите Go 1.22 или новее. Для реальной публикации используйте поддерживаемый выпуск; Dockerfile использует Go 1.26.
3. Выполните:

```bash
go version
go run ./cmd/server
```

4. Откройте сайт и админпанель:

| Адрес | Назначение |
|---|---|
| `http://localhost:8080/fi/` | Suomi - финская, основная |
| `http://localhost:8080/en/` | English - английская |
| `http://localhost:8080/admin` | Админпанель |

Начальный пароль: `12345`. При первом запуске создаётся папка `data/`. Перезапуск сохраняет контент и заявки. Удаление этой папки сбросит локальные данные; обычное обновление исходников не требует её удаления.

Если порт занят:

```bash
PORT=8090 go run ./cmd/server
```

Для настроек окружения можно скопировать `.env.example` в `.env`, заполнить значения и запустить:

```bash
bash scripts/run-local.sh
```

Обычный `go run` сам по себе не читает `.env`. Файл читает именно `run-local.sh`. В `.env` нельзя помещать непроверенные shell-команды.

## 3. Открытие в GoLand

Откройте всю папку `svm-rakennus` через File / Open. Настройте установленный Go SDK. Основной исполняемый пакет - `cmd/server`.

Для запуска создайте конфигурацию Go Build: Package path `svm.rakennus/site/cmd/server`; рабочая директория - корень проекта. В Environment задайте `PORT=8080`, `DATA_DIR=data`, при необходимости SMTP-переменные.

HTML находятся в `web/templates`, стили и клиентский код - в `web/static`. Модули npm не требуются. Для проверки JavaScript достаточно Node.js. Изменения HTML/CSS/JS в исходниках требуют перезапуска Go-процесса, поскольку файлы встроены через go:embed. Изменения контента из админпанели применяются без пересборки.

## 4. Подготовка Google Cloud

Нужны Google Cloud project с активным billing, доступ к Cloud Shell и права на создание Cloud Run, Firestore, Cloud Storage, service accounts, IAM bindings и Secret Manager. Если проект управляется организацией, эти действия может выполнить её администратор.

Используйте отдельное имя сервиса. Проект не направляет изменения автоматически в ваш существующий AutoHelp: конкретный Project ID вы указываете сами. В инфраструктуре создаётся именованная база Firestore, а не изменяется база `(default)`.

Загрузите архив в Cloud Shell и выполните из директории с архивом:

```bash
unzip SVM-Rakennus-Go-CloudRun.zip
cd svm-rakennus
gcloud auth list
bash scripts/bootstrap-gcloud.sh YOUR_PROJECT_ID
```

`YOUR_PROJECT_ID` замените на реальный ID. Название компании или номер проекта не заменяет Project ID.

По умолчанию сервис и база называются `svm-rakennus`, регион - `europe-north1`. Свои значения можно передать так:

```bash
bash scripts/bootstrap-gcloud.sh YOUR_PROJECT_ID my-build-site europe-north1
```

Имя сервиса ограничено 22 символами, потому что на его основе создаются service accounts. Используйте строчные латинские буквы, цифры и дефисы; начинайте с буквы.

Скрипт включает API, создаёт закрытый bucket, runtime и build service accounts, выдаёт им необходимые права и создаёт секреты. Первоначальный пароль вводится без отображения; пустой ввод выбирает `12345`. Измените этот пароль до использования сайта с реальными клиентами.

Инфраструктура записывается в `.deployment.env`. Этот файл содержит идентификаторы ресурсов, а не пароли. Сохраните его для дальнейших обновлений. Если IAM только что изменён, Google может потребовать некоторое время на распространение прав; при permission error проверьте права и повторите шаг развертывания.

## 5. Публикация Go-сайта

Из той же папки:

```bash
bash scripts/deploy-cloud-run.sh
```

Скрипт запускает Go-тесты, собирает контейнер через Cloud Build и публикует его в Cloud Run. После завершения выводятся адрес сайта и `/admin`.

Параметры выпуска: 1 vCPU, 1 GiB, concurrency 8, минимум 0 и максимум 3 экземпляра, timeout 120 секунд. SMTP выполняется внутри запроса, поскольку Cloud Run может приостановить CPU после ответа.

Сайт публично доступен по адресу Cloud Run, но демонстрационный режим запрещает индексацию. Админ-API требует пароль. Сам bucket всегда остаётся закрытым, а доступ к файлам проходит через приложение.

Здесь не требуется монтировать файловый диск или GCS FUSE. Контент хранится через Firestore REST, файлы - через GCS REST. Код отказывается запускаться в production без облачного хранилища и секретного ключа сессий, чтобы случайно не потерять данные в эфемерном диске контейнера.

Повторная публикация исходников:

```bash
bash scripts/deploy-cloud-run.sh
```

Обновление контента через админпанель повторной публикации не требует. Скрипт использует update-env-vars и update-secrets, поэтому уже настроенные SMTP-параметры сохраняются.

## 6. Домен и canonical

Сначала настройте реальную маршрутизацию домена на Cloud Run через поддерживаемый способ Google Cloud: domain mapping в доступном регионе либо внешний Application Load Balancer. Заполнение домена в админпанели не изменяет DNS и не создаёт TLS-сертификат.

Когда домен уже открывает сайт, укажите в «Компанія та контакти»:

```text
https://your-domain.fi
```

Не добавляйте завершающий `/`, путь, query string или `#`. Этот адрес используется для canonical, sitemap, социальных изображений и ссылок в email.

До подключения домена можно временно использовать HTTPS-адрес самого Cloud Run. После подключения собственного домена обновите canonical. Организуйте перенаправление с дополнительного домена на основной на уровне hosting/load balancer, если используете несколько доменов.

## 7. Первый вход и основные настройки

Откройте `/admin` и войдите с первоначальным паролем. Данные по умолчанию уже созданы: все текстовые поля, разделы, шесть услуг, примеры портфолио и изображения.

В «Компанія та контакти» заполните название, юридическое название, Y-tunnus, контактное лицо, телефон, email, регион, адрес, домен и ссылки на соцсети. Замените логотип и фотографии. Отдельный email для заявок может отличаться от публичного email.

В «Система» поменяйте пароль. Новый пароль должен содержать 12-256 символов. После изменения завершаются существующие сессии, включая текущую. Войдите снова с новым паролем.

ADMIN_PASSWORD используется только при создании первой записи. После этого пароль хранится в виде хеша в Firestore. Изменение секрета ADMIN_PASSWORD не заменяет пароль уже существующего сайта. Для штатной смены используйте админпанель; аварийное восстановление описано отдельно.

## 9. Тексты и две языковые версии

Во вкладке текстов выберите нужный блок. По умолчанию показаны Suomi и украинский перевод; можно включить английскую версию, все поля или один публичный язык. В полях заголовка можно использовать перенос строки для композиции. В длинных текстах два переноса строки разделяют абзацы.

Сайт не выполняет автоматический перевод. Изменяя предложение, проверьте обе версии. При пустом финском значении отдельного двуязычного поля используется английское; основные системные строки должны оставаться заполненными.

Тексты считаются обычным текстом. HTML и JavaScript не исполняются. Вставленный `<script>` не станет кодом страницы.

Служебные ключи вроде `hero.title` или `form.success` помогают понять назначение поля. Ключи менять не нужно, изменяйте только их содержимое.

## 10. Услуги, объекты и фотографии

Добавление создаёт скрытую запись, чтобы незавершённая страница не появилась на сайте. Заполните оба языка, выберите обложку и включите публикацию. Сохраните настройки, затем откройте страницу кнопкой EN или FI.

URL slug должен содержать строчные латинские буквы, цифры и дефисы. При изменении опубликованного slug сервер автоматически создаёт 301-перенаправления старых EN/FI URL. История redirect-правил видна в SEO; сервер отклоняет циклы.

Внутренний ID используется в заявках и событиях. Не меняйте его после того, как страница начала использоваться.

У объекта можно заполнить место, площадь, год и галерею. Не публикуйте сведения, которых нет. Отключайте отметку демонстрации только для настоящих проектов. Тексты «Иллюстративный пример» скрываются после снятия этой отметки, а объект получает возможность индексации после общего включения SEO.

Файлы: JPG/JPEG, PNG, WebP, GIF и PDF, до 8 MB каждый. Изображения проверяются по сигнатуре, заголовку и размерам. Для загрузки выберите файл с ПК; при нескольких файлах загрузка идёт последовательно. Встроенные изображения также находятся в выборе медиа.

Рекомендуемые размеры: обложка первого экрана примерно 1600-2400 px по ширине; фотографии объектов от 1200 px. Оптимизируйте размер файла заранее. Автоматического изменения размера, WebP-конвертации и редактирования EXIF в этом выпуске нет.

SVG из загрузок не принимается. Логотип подготовьте в PNG/WebP, при необходимости с прозрачностью. Встроенный favicon SVG является частью доверенного кода; собственный favicon можно выбрать как PNG/WebP.

Публичный файл, на который ссылается текущий сохранённый контент, нельзя удалить. Сначала замените его в блоках, сохраните, затем удаляйте из медиабиблиотеки. Вложения заявок удаляются вместе с заявкой, а не через публичную библиотеку.

## 11. Email и SMTP

Почта требует вашего SMTP-провайдера и подтверждённого отправителя. Код готов для SMTP через STARTTLS на 587/2525 либо implicit TLS на 465. Незашифрованное соединение не поддерживается.

В Cloud Shell:

```bash
bash scripts/configure-email.sh
```

Введите host, port, login, verified sender email и пароль. Пароль вводится скрыто и сохраняется в Secret Manager. Скрипт не выводит его на экран.

После этого заполните email получателя в админпанели, сохраните изменения и нажмите «Надіслати тестовий лист» в «Система». Ошибка теста показывает этап сбоя: соединение, TLS, авторизация, отправитель или получатель.

Без SMTP форма продолжает сохранять заявки. Статус email будет `failed`. Владелец видит обращение в кабинете и может повторить отправку после настройки почты.

В email есть номер обращения, время UTC, имя, контакты, услуга, описание и ссылка на админпанель. Reply-To содержит email клиента, чтобы ответить напрямую. Приватные файлы передаются ссылками, требующими входа.

Опциональное письмо клиенту включается в настройках. Его текст редактируется в группе confirmation на обоих языках. Эта дополнительная доставка не имеет отдельной очереди повторов; основное уведомление владельцу отслеживается в заявке.

## 12. Заявки и обработка

Форма проверяет имя, email, описание от 10 символов и подтверждение ознакомления с privacy notice. Телефон, компания, услуга и файлы необязательны. На заявку можно приложить до трёх файлов по 8 MB.

Запись создаётся до попытки отправить email. Поэтому проблема с почтой не удаляет лид. Повтор одного запроса после сетевого сбоя использует тот же ключ и не создаёт дубль. После успешной отправки форма очищается, а событие generate_lead получает уникальный ID записи.

Статусы в кабинете: «Нове» (новая), «Зв’язалися» (связались), «Кошторис» (смета), «Успішно» (успешно), «Відмова» (отказ), «Спам». Заметки доступны только владельцу. Можно искать по контактам, имени, компании и сообщению, фильтровать по статусу, экспортировать CSV.

В базе дата хранится в UTC. В кабинете она отображается в Europe/Helsinki с корректными сезонными смещениями времени. Письмо явно показывает UTC, чтобы источник времени был понятен.

При статусе email `sending` не отправляйте повтор немедленно: возможна незавершённая попытка. Подождите 15 минут и проверьте mailbox. Если письмо пришло, повтор не нужен.

Очистка по сроку хранения запускается вручную в «Система», с отдельным подтверждением. 0 дней отключает её. Настройка срока сама по себе не запускает плановую очистку.

## 13. SEO и публикация для поиска

Начальное состояние: demo включён, indexing выключен. Это позволяет собрать правильные реквизиты, тексты и фотографии до попадания шаблона в поиск.

Для запуска заполните реальный домен и email, юридические страницы, настоящие объекты, затем отключите demo и включите indexing. Сервер отклонит включение индексации без реального домена и email.

У главной страницы и каждой услуги/объекта есть Title, Description и social image для EN/FI. Пустые SEO-поля страницы услуги/объекта используют название, краткое описание и обложку. Общий robots настраивается отдельно.

| Элемент | Поведение |
|---|---|
| Canonical | Основной домен и текущая языковая страница, без marketing query |
| Hreflang | EN, FI и x-default на выбранный основной язык |
| Open Graph / Twitter | Название, описание, URL, большая картинка |
| JSON-LD | WebPage; компания при отключении demo; Service для услуг |
| Sitemap | Только включённые реальные страницы EN/FI; примеры объектов исключаются |
| Robots | Demo закрывает весь сайт; после запуска закрываются admin и api |
| Перенаправления | Автоматические при смене slug; можно добавить внутренние правила вручную |
| Админка и API | noindex через HTTP-заголовки; API требует авторизацию |

Проверьте `/robots.txt` и `/sitemap.xml` после сохранения. Sitemap пуст в демонстрационном режиме - это ожидаемое поведение.

В Google Search Console добавьте домен, подтвердите владение и отправьте URL `/sitemap.xml`. Это делается в аккаунте владельца. Код сайта не подключает Search Console и не гарантирует позиции или мгновенную индексацию.

## 14. GA4, Ads, Meta, LinkedIn и TikTok

Во вкладке аналитики задайте только ID реально используемых платформ. Оставленное пустым поле не загружает соответствующий SDK.

| Платформа | Что вводить |
|---|---|
| Google Analytics 4 | Measurement ID `G-...` |
| Google Ads | Google tag ID `AW-...`; conversion label в строке события |
| Google Tag Manager | Container ID `GTM-...` и режим GTM |
| Meta | Pixel ID, только цифры |
| LinkedIn | Partner ID и отдельные conversion_id для событий |
| TikTok | Pixel ID и имя события |

Google имеет два режима: direct либо GTM. В direct сайт самостоятельно загружает GA4/Ads и отправляет события. В GTM прямые Google-теги отключаются, а dataLayer передаёт события для ваших настроек контейнера. GTM в этом проекте загружается только при согласии и на аналитику, и на рекламу.

Meta, LinkedIn и TikTok работают через прямые SDK и в режиме Google GTM. Если хотите управлять ими целиком через GTM, очистите соответствующие прямые ID и настройте теги в контейнере. Не включайте обе реализации одновременно.

## 15. Таблица событий

| Событие сайта | Когда возникает | Значение по умолчанию |
|---|---|---|
| generate_lead | Только после сохранения заявки | GA4 generate_lead; Meta Lead; TikTok Lead |
| phone_click | Клик по телефону | GA4 phone_click; Meta/TikTok Contact |
| email_click | Клик по email | GA4 email_click; Meta/TikTok Contact |
| file_download | Клик по документу | GA4 file_download; TikTok Download |
| form_start | Первое взаимодействие с формой | GA4 form_start |
| service_view | Просмотр страницы услуги | GA4 service_view; Meta/TikTok ViewContent |
| project_view | Просмотр страницы объекта | GA4 project_view; Meta/TikTok ViewContent |
| scroll_depth | Пороги 25%, 50%, 75%, 90% | GA4 scroll_depth |

Можно отключить строку или отдельное направление, оставив имя события пустым. Google Ads conversion label и LinkedIn conversion_id пусты до вашей настройки. Они не совпадают с Measurement ID или Partner ID.

Для основной заявки заполните её Ads label и LinkedIn conversion_id. В GA4 отдельно отметьте generate_lead как key event. При импорте этой конверсии из GA4 в Ads и одновременном использовании прямой Ads-конверсии задайте одну основную цель, чтобы не считать одну заявку дважды в отчётности кампании.

Сайт не отправляет имя, телефон, email и текст обращения в payload своих аналитических событий. Передаются язык, путь страницы, контент, глубина прокрутки и непрозрачный ID события. GA4 получает URL без произвольных query-параметров; стандартные UTM сохраняются, а Google advertising click IDs включаются при согласии на рекламу.

Автоматическое расширенное измерение GA4 и любые теги, добавленные владельцем в GTM, настраиваются в соответствующих аккаунтах. Не включайте автоматическое измерение форм, если оно дублирует события проекта. Серверные CAPI/Events API и enhanced conversions в этот выпуск не включены.

## 16. Cookies и согласие

До выбора посетителя аналитические и рекламные SDK не загружаются. Есть независимые переключатели analytics и marketing, кнопки принять все, отклонить необязательные и сохранить выбор.

Выбор хранится в localStorage максимум 180 дней. Необходимые admin cookies используются только для входа владельца. GTM имеет консервативный общий gate по двум категориям, описанный выше.

При отзыве уже выданного разрешения страница перезагружается, чтобы выгрузить сторонние библиотеки. Ранее созданные сторонние cookies могут потребовать очистки в настройках браузера или провайдера; локальный banner не способен удалить cookies чужого домена.

Privacy, cookies и terms представлены черновиками. Перед запуском замените их текстами, соответствующими вашей компании, фактическим провайдерам, обработке данных и договорным условиям. В финской версии черновики обозначены LUONNOS (черновик), в английской - DRAFT. Их нужно подготовить как реальные документы компании.

## 17. Резервные копии и данные

В «Система» есть экспорт контента JSON и импорт, включая украинские редакторские переводы и цвета темы. Экспорт не содержит пароль, ключ сессий, SMTP-пароль, заявки или байты фотографий. Он содержит ссылки на файлы.

Импорт загружает настройки как несохранённый черновик; сначала проверьте его, затем нажмите «Зберегти». Текущий пароль сохраняется, поскольку сервер не принимает auth из клиентского JSON.

Для полного backup нужны экспорт Firestore и копия Cloud Storage. Используйте механизмы Google Cloud и отдельный закрытый backup bucket. Пример после загрузки `.deployment.env`:

```bash
source .deployment.env
gcloud firestore export gs://YOUR_BACKUP_BUCKET/firestore \
  --project "$PROJECT_ID" --database "$SITE_DATABASE"
gcloud storage rsync "gs://$SITE_BUCKET" \
  gs://YOUR_BACKUP_BUCKET/media --recursive
```

Backup bucket заранее создаёт владелец; необходимые права и место хранения задаются отдельно. Экспорт Firestore и storage backup могут создавать расходы. Шаблон bootstrap включает object versioning для файлов. Удаление через сайт удаляет активную версию; резервные/неактивные версии и soft delete управляются политиками Google Cloud, а не интерфейсом сайта.

Локальный backup: остановите сервер и скопируйте всю `data/`, включая session-secret, а не только state JSON. Защитите копию от публичного доступа.

## 19. Типовые ошибки

| Ситуация | Действие |
|---|---|
| go command not found | Установить Go или проверить PATH |
| address already in use | Выбрать другой PORT |
| Публичный сайт работает, email failed | Настроить SMTP и email получателя; выполнить тест |
| SMTP authentication failed | Проверить именно SMTP login/password, а не обычный пароль почты |
| SMTP sender rejected | Подтвердить адрес/домен отправителя у провайдера |
| Cloud API 403 | Проверить runtime IAM для Firestore и bucket, секреты и выбранный Project ID |
| Cloud Build permission denied | Проверить build service account, roles/run.builder и право deployer actAs |
| Контент изменился в другой вкладке | Обновить настройки; не пытаться обходить revision guard |
| Sitemap пуст | Проверить demo, indexing и baseUrl |
| GA/Ads не видны | Проверить cookies, ID, режим Google, цели и блокировщики браузера |
| Нельзя удалить фото | Убрать ссылки на него из сохранённых блоков/SEO/галерей |
| После смены SMTP всё ещё старые настройки | Проверить успешную новую Cloud Run revision |
| Начальный пароль не работает после смены | Использовать текущий пароль; ADMIN_PASSWORD не сбрасывает существующий хеш |

Логи процесса:

```bash
source .deployment.env
gcloud run services logs read "$SITE_SERVICE" \
  --project "$PROJECT_ID" --region "$SITE_REGION" --limit 50
```

## 20. Аварийное восстановление пароля

Штатный способ - «Система» в админпанели. При утере пароля используйте `scripts/reset-admin-password.py` из Cloud Shell с правами на данную базу Firestore:

```bash
source .deployment.env
python3 scripts/reset-admin-password.py \
  --project "$PROJECT_ID" --database "$SITE_DATABASE" \
  --namespace "$SITE_NAMESPACE"
```

Скрипт запрашивает новый пароль скрыто, обновляет хеш и увеличивает auth version. Старые сессии перестают действовать. Контент и заявки не удаляются. Он использует токен текущего gcloud account в памяти, а не хранит его в файле.

## 22. Финские тексты и украинская админпанель

Интерфейс кабинета - украинский. Основная публичная версия - финская; английская открывается переключателем FI / EN. Корень сайта перенаправляет на /fi/ с сохранением UTM-параметров. Hreflang x-default ведёт на соответствующую финскую страницу.

В «Тексти та сторінки» по умолчанию показаны две колонки: Suomi (финская) и переклад українською. Украинская колонка - редакторская подсказка; посетителям она не показывается и отдельного маршрута /uk/ нет. Можно включить отображение английской версии или всех трёх редакторских полей.

При изменении финского текста украинский перевод обновляйте вручную. Сайт не вызывает платные сервисы перевода. Во вкладках услуг, объектов и FAQ английская версия находится в раскрывающемся блоке. Значения украинских полей сохраняются вместе с настройками и входят в резервный JSON.

| Saneeraus | Реновація, комплексне оновлення |
| Purkutyöt | Демонтажні роботи |
| Palokatkotyöt | Протипожежна герметизація проходок |
| Parvekelasitus | Скління балкона |
| Kustannusarvio | Кошторис, попередня оцінка вартості |

Вкладка «Фінські терміни» содержит более 60 терминов и поиск по финскому или украинскому слову. В общих настройках есть пояснения к контактам, изображениям и настройкам оформления.

Клиентское подтверждение, если включено, использует язык заполненной формы. В CSV есть отдельная колонка времени Гельсинки.
